# Overall Development Strategy

We'll follow this pattern for every feature:

```text
1. Understand the requirement
            ↓
2. Design Database
            ↓
3. Build Backend API
            ↓
4. Test with Postman
            ↓
5. Build Frontend Page
            ↓
6. Connect Frontend to Backend
            ↓
7. Test Complete Flow
```

That way, you'll always know **why** the frontend is making an API call and what happens after it.

# One More Change I'd Like to Make

I think we should also maintain a small learning notebook as we go.

For every concept, we'll write:

```text
Concept:
JWT

Definition:
A signed token used for authentication.

Used In:
Login

Example:
jwt.sign(...)
```

Similarly for:

* Middleware
* bcrypt
* req.body
* req.params
* req.query
* JWT
* Authorization Header
* Foreign Key
* Primary Key
* SQL JOIN
* async/await

## One important thing I want to change from now onwards

I want to make you think before coding.

Instead of me giving code immediately, I'll often ask:

> "How do you think we should do this?"

Then I'll correct or improve your answer.

That's much closer to how you'll work in an actual software engineering job, and it will make you much more confident in interviews.

I genuinely think you're at the stage where this approach will help you more than just copying code.
